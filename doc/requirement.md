# quickchart 要求仕様

## 1. 背景・目的

コンサルティング資料でよく使われる図解パターン(マトリクス、ピラミッド、ロジックツリー、ベン図など)を、効率よく作図するためのデスクトップアプリケーションを開発する。

汎用のドローツール(PowerPoint、draw.io、Miro等)は自由度が高い反面、コンサル資料特有の「型」を都度手作業で組み立てる必要があり時間がかかる。本ツールは、汎用的な作図の自由度を保ちながら、頻出パターンをテンプレート/自動生成で素早く組み立てられることを目指す。

## 2. 対象ユーザー

- コンサルタント、企画職など、提案資料・社内資料で図解を多用するビジネスパーソン
- 自分自身(開発者)を含む、資料作成を効率化したい個人ユーザー

## 3. スコープ

### 3.1 MVP方針

- **汎用図形エディタを土台とする**。矩形・矢印・テキスト・コネクタ・線・円/楕円などの基本パーツを自由配置・変形・接続できるキャンバスをまず固める。
- その上で、**構造化データからの自動レイアウト生成**(両対応方針)にも対応する。頻出パターン(マトリクス、ピラミッド、ロジックツリー等)は、階層テキストなどの構造化入力から雛形を自動生成し、生成後は自由配置キャンバス上で微調整できるようにする。
- 全パターン(ガントチャートやグラフ類を含む)を最初から網羅するのではなく、まず作図基盤とコア数パターンの自動生成を固め、段階的に対応パターンを拡張する。

### 3.2 対象図解パターン一覧

| カテゴリ | パターン(ライブラリ上の表示名) | MVP扱い |

| 基本 | 箇条書きマトリクス(行見出し×列見出しの各セルに箇条書き) | 構造化テンプレート化(MVP) |

| 比較 | ビフォーアフター(縦/横。導入前後・現状と施策の対比) | 構造化テンプレート化(MVP) |
| 比較 | 比較表、MECE図解 | 表パーツ+ロジックツリー流用(MVP〜将来) |
| データ | グラフ類(棒・折れ線・円・100%積み上げ・ウォーターフォール) | 専用チャートパーツ(将来) |

- 「ツリー図」と「ピラミッド図」は別パターンである。ツリー図は親子関係を持つ木構造(いわゆるピラミッドストラクチャー)、ピラミッド図は三角形を段に分けた図形そのものを描くパターンを指す。
- 「汎用フローチャート」(分岐・合流を含む)は汎用パーツ+コネクタで手動作図し、分岐のない一直線のステップ図のみ「フロー図」テンプレートで自動生成する。パターンライブラリの「フローチャート」(スケジュール系)は、矢羽根型の工程見出しと詳細・所要期間からなる工程図を指し、分岐・合流を含む汎用フローチャートとは別物である。
- パターンライブラリ上では、スケジュール系のパターン(ガントチャート、フロー図、フロースケジュール、タイムライン、フローチャート)を「スケジュール」グループのサブメニューにまとめて表示する。

## 4. 機能要件

### 4.1 キャンバス・図形操作(自由配置)

| 機能 | 受け入れ条件 |
|---|---|
| 基本図形(矩形、角丸矩形、円/楕円、直線、矢印、コネクタ、テキストボックス)の作成・移動・リサイズ・回転 | 各図形をツールから配置でき、選択後にドラッグで移動、ハンドルでリサイズ・回転できる |
| ツール切り替えUI | 名前付きボタンを横/縦に並べる方式ではなく、アイコンボタン+コマンドパレット(検索・キーボード操作でツールを呼び出せるUI)で構成し、パネルをコンパクトに保つ。全ツールをアイコンとコマンドパレットの両方から選べる |
| 図形同士の接続 | 図形に接続したコネクタが、接続先の図形を移動・リサイズしても端点を追従させる |
| 整列・分布、グリッドスナップ、ガイド線 | 複数選択時に左/中央/右・上/中央/下揃えと水平/垂直の等間隔分布ができる。移動時にグリッドへ吸着し、他の図形の端・中心と揃う位置にガイド線を表示する |
| グルーピング/グループ解除 | グループ化した図形群をまとめて選択・移動でき、解除すると個別の図形に戻る |
| レイヤー順序(最前面/最背面/前面へ/背面へ) | 重なった図形の表示順を4種の操作で変えられる |
| 複製、コピー&ペースト | 選択図形を同じタブ内で複製・貼り付けできる。**別のタブへのコピー&ペーストもできる**(4.7参照) |
| Undo/Redo | 図形・テキストの変更操作をUndo/Redoでき、Undoを繰り返した後にRedoを繰り返すと元の状態に戻る |
| ズーム、パン | キャンバスを拡大・縮小・スクロールでき、図形の座標は変わらない |

### 4.2 構造化テンプレート生成

- フローは「①図解パターンを選択 → ②パターン固有の階層テキストを入力 → ③自動レイアウトで生成」の順とする
- 階層テキストの意味付け(インデントが何を表すか)はパターンごとに異なる。単一の汎用フォーマットで全パターンを賄うのではなく、パターンごとに専用の解釈規則を定義する
  - ピラミッド/ロジックツリー: インデント=親子関係。階層テキストがそのまま木構造として解釈される
  - マトリクス: 1階層目=象限、2階層目=各象限の項目。縦軸・横軸のラベルは階層テキストではなくパターン固有の入力欄で指定する
  - ベン図: 1階層目=集合名、2階層目=要素。複数集合に同一要素を記載すると重なり領域として扱う
  - その他のパターン: パターンごとの解釈規則は設計(spec §6.2)で定める
- 生成後は自由配置キャンバス上の通常図形として編集可能(テンプレート専用オブジェクトに固定しない)
- 元データとの同期方針
  - テキスト内容(ラベル等)は、元の階層テキストと図形側で双方向に同期する(どちらを編集しても他方に反映される)
  - 配置・サイズ・色などの図形としての形状変更は図形側のみに保持され、元の階層テキストにはフィードバックされない(形状の同期は行わない)
  - 形状非同期の原則に対し、以下は**許容する例外**とする(いずれもUndoで元に戻せる)
    - 階層テキストの一括インポート(外部テキストの貼り付け)を行うと、そのブロックの図形はすべて作り直され、手動で調整した配置・サイズ・色は失われる
    - ツリー図・ロジックツリー図以外のパターンでは、階層テキスト側でノードを追加・削除・並べ替えすると、表やグリッドとしての整合を保つためブロック全体を再レイアウトする。このとき手動で調整した配置・サイズは失われる
    - ベン図では、要素テキストの編集によって所属する集合の組み合わせが変わった場合、該当要素の位置を再計算する
- テンプレートごとのパラメータ調整は、パターンの構造を変えない範囲の項目に限る(例: ベン図の集合数(2〜3)、全体タイトル、マトリクスの軸ラベル、ガントチャートの月の範囲)
  - マトリクスは4象限固定、ベン図は2〜3集合までとし、象限数の変更や4集合以上のベン図は対象外とする

### 4.3 スタイル・書式

- 塗り色、線色、線太さ、線種(実線/破線)
- フォント、文字サイズ、文字色、配置(中央揃え等)
- 配色テーマ(コンサル資料向けの落ち着いた配色プリセットを複数用意)
  - テーマ切り替えは、以後新規作成する図形のデフォルト色に適用される。既存図形の色は遡って変更しない(図形ごとに独立した色として保持されるため)
- スタイルのコピー(書式のコピペ)

### 4.4 テンプレート/パターンライブラリ

- 3.2の図解パターンをライブラリパネルから選択して配置
- よく使う図形の組み合わせをユーザー自身がテンプレート登録できる

### 4.5 出力・エクスポート

独自プロジェクトファイルを正(マスター)とし、以下はすべて「エクスポート」(別ファイルへの書き出し)として位置付ける。エクスポート後にそのファイルを編集しても、元のプロジェクトファイルには反映されない。

エクスポートの対象は、**アクティブなタブの図のみ**とする(複数タブの一括エクスポートは行わない)。

- SVGファイルへのエクスポート(再編集可能なベクター形式)
- PNG画像へのエクスポート(解像度指定可)
- PowerPointへの貼り付け対応(EMFファイルへのエクスポート、およびクリップボード経由の貼り付け。貼り付け後もPowerPoint側で編集可能な図形として出力)
  - 以下は**許容する制限**とする
    - PowerPointに貼り付けた図形を「グループ化解除」すると、テキストの左/中央/右揃えが左揃えになる(PowerPoint側の変換仕様による)。グループ化を解除しなければ正しく表示される
    - EMFの生成・クリップボード転送に失敗した場合は、エラーを通知しPNGエクスポートを案内するに留め、PNGへの自動切り替えは行わない

### 4.6 プロジェクト管理

- 独自プロジェクトファイル(拡張子 `.qct`、JSON形式)を正式な保存形式とする。新規作成・開く・保存・名前を付けて保存はこのファイルに対して行う
- 複数タブ対応前の形式(タブを持たない単一の図)で保存されたファイルも開けること。開いた場合はタブ1つのプロジェクトとして扱う
- 直近使用ファイル一覧

### 4.7 複数タブでの編集

- 1つのプロジェクトファイルは、複数の独立した図(ページ)をタブとして保持できる。1タブ=1つの自由配置キャンバス全体(構造化テンプレートで生成した図形を含む)に対応する
- タブは自由に追加・削除・並べ替え・名前変更ができる(上限なし)
- 新規作成時は、常にタブ1つ(空の図)から開始する
- ファイルを開いた場合は、そのファイルに保存されているタブ構成(タブ数・順序・名前・各タブの図の内容)をそのまま復元する
- 最後の1枚のタブを閉じることはできない(常に最低1タブは残る)
- 図形を1つ以上含むタブを閉じようとした場合(×ボタン、`Ctrl+W` のいずれでも)は、「閉じる」「キャンセル」の2択で確認する。「閉じる」を選ぶとタブとその内容を破棄し、「キャンセル」を選ぶと何もしない。図形を含まない空のタブは確認なしに閉じる
- 図形のコピー&ペーストはタブをまたいで行える(あるタブでコピーした図形を別のタブに貼り付けられる)
  - 構造化テンプレートで生成した図形を貼り付けた場合、貼り付けた図形は元の階層テキストと同期しない通常の図形として扱う(同じタブ内での貼り付け・複製も同様)
- 保存は複数タブ横断で単一のプロジェクトファイルに対して行う。いずれかのタブに未保存の変更があれば、ファイル全体が「未保存」の状態として扱われる
- 同時に編集できるプロジェクトファイルは1つのみとする(複数のファイルを同時に開いて編集することはしない)
- 編集中のファイルとは別のファイルを開こうとした場合(新規作成、既存ファイルを開く、直近使用ファイル一覧からの選択のいずれの操作でも)、以下の流れで切り替える。**アプリケーションを終了しようとした場合(ウィンドウを閉じる操作)も同じ流れで確認し、「切り替える」を「終了する」と読み替える**
  1. 現在のファイルに未保存の変更があれば、「保存する」「保存しない(変更を破棄)」「キャンセル」の3択で確認する
  2. 「保存する」を選んだ場合は保存を実行してから、目的のファイルの編集に切り替える(タブ構成も目的のファイルのものに総入れ替えする)
  3. 「保存しない」を選んだ場合は現在の変更を破棄して、そのまま目的のファイルの編集に切り替える
  4. 「キャンセル」を選んだ場合は何も行わず、現在のファイルの編集を継続する
  - 未保存の変更がない場合は、確認なしにそのまま切り替える(終了の場合はそのまま終了する)
  - 「保存する」を選んだが保存が完了しなかった場合(名前を付けて保存ダイアログのキャンセル、保存失敗)は、「キャンセル」と同様に現在のファイルの編集を継続する

## 5. 非機能要件

- Tauriによるデスクトップアプリケーション。対応OSはWindowsに限定する(PowerPoint貼り付け対応がWindows固有のEMFフォーマットに依存するため)
- オフラインで完結して動作すること(外部サービスへの依存を持たない)
- 大きめの図(数十〜百オブジェクト規模)でも操作がもたつかないこと、アプリケーション起動時間・保存/読込の応答性が実用レベルであること
  - MVPでは具体的な数値目標は定めず、ベストエフォートとする。数値目標が必要になった場合は将来のパフォーマンス検証フェーズで設定する

## 6. 技術スタック

- バックエンド: Tauri (Rust)
- フロントエンド: React + TypeScript
- 図形描画: SVGをDOMとして直接操作する方式を基本とする(具体的な描画/操作ライブラリの選定は設計フェーズで検討)

## 7. UI構成(想定)

- 左パネル: 図形ツール(アイコン+コマンドパレット、4.1参照) / パターンテンプレートライブラリ
- 中央上部: タブバー(プロジェクトファイル内の複数の図を切り替え、4.7参照)
- 中央: キャンバス(自由配置エディタ)
- 右パネル: 選択オブジェクトのプロパティ(スタイル、位置・サイズ)
- 上部: ツールバー(保存、エクスポート、Undo/Redo、ズーム)

## 8. スコープ外(当面対応しない)

- クラウド共同編集・リアルタイムコラボレーション
- モバイル対応
- macOS / Linux対応(対応OSはWindowsに限定)
- アニメーション機能
- 高度なグラフ描画(複雑な統計チャート等、将来検討の中でも優先度低)
